# Authentication and renewal

## Storage and renewal

Acc saves its accounts in `~/Library/Application Support/Acc/accounts.json`. This contains OAuth secrets in encoded JSON; **it is not an encrypted vault**. The directory is private (`0700`), files are private (`0600`), and writes use an atomic same-directory replacement. Native provider credentials retain the provider's storage format. Tokens are never written to diagnostic output or account-list JSON. There is no telemetry or remote logging.

The core serializes Acc operations across processes, reads the active native login before refreshing, and writes a private recovery copy of successful rotations before updating the vault and native store. If the primary vault update is interrupted, the recovery copy is replayed on the next load without another exchange. Recovery copies are removed after a successful vault save. If writing the recovery copy fails, Acc still attempts to save the primary vault. If publication fails, the next refresh can use the already-saved result, including partial Claude Keychain/file/metadata publication. Native writes check that the login has not changed since it was read. Provider clients do not honor Acc's lock, so this reduces rather than eliminates races with simultaneous provider refreshes. Reauthentication is available if the provider rejects a refresh token.

Codex renews at the earlier of five days since its last renewal and 120 hours before access-token expiry. Claude renews one hour before expiry, with the same five-day maximum age. The one-hour lead is Acc's default to leave time for transient failures and retries; it is not a provider requirement. All timing values are configurable. A token whose known lifetime is shorter than its renewal margin renews halfway through that lifetime to avoid continuous renewal. Without an expiry, the last renewal or JWT issue time provides the five-day anchor; if neither is known, renewal is due immediately. An expiry-bearing credential with no issue/renewal timestamp uses the first observation as its maximum-age anchor. Permanent refresh rejection pauses automatic rotation until credentials change or the user explicitly retries.

The older ten-minute Claude default upgrades once to one hour. Older vaults did not distinguish a default from an explicitly selected ten minutes; custom values are retained, and a ten-minute choice made in this version is retained on later launches.

Active usage is checked about every two minutes while Acc is running, with five-minute checks for alternate accounts. Opening Accounts or changing providers checks the selected provider's usage when its last reading is at least thirty seconds old. Provider retry deadlines still take precedence. This follows the recent-interaction cadence in [CodexBar's refresh policy](https://github.com/steipete/CodexBar/blob/main/Sources/AdaptiveRefreshCore/AdaptiveRefreshPolicyCore.swift). Usage failures retain the previous snapshot and mark it stale in both the account row and menu bar. Usage and token renewal have independent retry schedules, so a failure in one does not delay the other. A usage rejection triggers at most one token rotation per update. Passed reset times trigger a new check and mark the old measurement stale; missing windows remain unavailable. Acc never invents a quota or treats absent data as 100% remaining.

**Detach**, **Remove**, and **Sign out locally** have different effects. Detach keeps the saved account but pauses Acc’s automatic updates, allowing normal provider login/logout without Acc managing that copy. Remove deletes only Acc’s saved copy and prevents automatic recapture when switching away; adding it explicitly again restores management. Sign out locally saves the outgoing OAuth login and clears the provider’s local credentials; it does not revoke the server-side session. Switching a detached account resumes management. A provider’s own logout may revoke saved refresh tokens, in which case sign in again.

## Replacing Codex Auth Guard

Import the **latest** managed JSON for each account using **+ → Import from File…**, or save the active login. Import copies it into Acc; Acc does not continue writing the original Auth Guard profile file. Avoid leaving two refreshers managing the same token lineage. Each saved account must be attached, **Keep saved accounts fresh** enabled, and **Open at login** actually enabled in macOS. The account’s details show when Acc last checked and renewed it and when it will renew next.

The UI defaults favor continued renewal: native Keychain/file read failures do not prevent renewal of saved credentials. A setting can require native availability instead. Acc defers native publication until that store is accessible, and never publishes into a different active identity. Provider rate limits are honored. Permanent invalid/revoked/reused refresh-token errors require sign-in; Acc cannot make a provider-revoked session valid again. Refresh-token expiry is not exposed by these providers, so the date shown is explicitly **access-token** expiry.

**Old tokens are not a rollback.** Once a provider consumes a refresh token, keeping its old JSON cannot restore the session. The recovery file holds only **new credentials returned by a successful exchange**. A timeout/lost response, server/gateway failure, malformed success response, or a crash during an unfinished exchange leaves the outcome unknown. Acc records this and pauses automatic replay of the old token; it reconciles a newer native login if one becomes available. Sign in again, explicitly retry once, or opt into **Retry renewals with an unknown outcome** (off by default). A definite failure to connect before a request can be delivered can retry normally. No file backup can recover new tokens that the server issued but Acc never received.

Opening another UI action does not cancel a token exchange. Browser consent can remain open while other accounts continue to receive maintenance. Successful renewal state and the last 20 renewal outcomes survive restarts. No process-name checks, network probe gates, condition files, minimum 24-hour token requirements, or extra execution acknowledgements were imported from Auth Guard.
